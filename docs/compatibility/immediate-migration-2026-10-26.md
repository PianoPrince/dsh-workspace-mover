## 迁移后的当前对话

官方 SessionController 在 dispose 时发布 api-session/removed；客户端 Session.handleRemoved 将 removed 置为 true，后续 added 事件只更新列表，并不清除此标记。因此后端已恢复的 Agent 对应的旧界面仍不可用。rc.3 在迁移 RPC 结束后检查仍选中的会话，仅在 removed 时通过 uiWorkspace.clearMain/openSession 释放旧视图并重新打开，等待新会话打开。失败回滚也执行同样检查；用户切换到其他会话或插件卸载后不主动跳转。不改宿主文件或私有 removed 字段。

rc.3 漏掉了延迟释放：clearMain 仅立即释放主视图引用，React Provider 的其他引用要等界面更新才释放，立刻 openSession 会重新持有 removed 的旧对象。rc.4 用 sessions.retainInfo 观察旧 binding 的实际退出后再打开；最多等待 3 秒，插件卸载会取消等待。等待期间用户选了其他会话则不重新打开。

新增已安装客户端验证：执行 Desktop 内的真实 ClientSessions / SessionManager / Session 代码，使用真实 Cordis，替换界面 store 和未使用的传输边界。确认 added 不清除 removed、双引用下同步重新取得旧对象、延迟释放最后引用后才能取得 removed=false 的新对象。该验证不运行 React 界面，不能替代 Desktop 复验。

若其他界面仍持有旧会话引用，或重新打开失败，明确提示彻底退出并重启，不重复执行物理迁移。自动回归覆盖成功、回滚、连接报错、用户切换、正常界面和插件卸载；完整 Desktop 界面、草稿及预设保持情况仍需实际验收。

## 行为

- 插件观察官方 agents.create/resume，保留返回的生命周期 dispose；不修改持久化 writer、不可变 Session header 或安装文件。
- 空闲且已接入生命周期的会话：锁定迁移操作，阻止新请求及后台恢复，等待官方 dispose 排空并关闭 writer，真实搬移档案，通过官方 SessionController.resolveAgent 重新按宿主预设加载。
- 运行中会话：弹窗明确显示“停止任务并迁移”；取消不调用迁移。状态在确认后发生变化时，后端返回 stop-required，不擅自停止。
- 放行操作使用 AsyncLocalStorage 限定为当前迁移的恢复调用，不放行其他并发恢复。旧 Agent 引用在替换后拒绝发送。
- 迁移失败沿用文件和工作区归属回滚，并请求宿主从原位置重新加载。若重新加载失败，明确返回错误，不伪称全部成功。
- 热更新前已打开、没有保留生命周期句柄的会话不强行释放。完全重启一次后重新打开会话即可接入；未知后端仍保留原安全检查。
- 拖动迁移不自动创建 pending。历史 API 的排队能力和已有队列保持兼容；没有明确停止授权的后台任务不取消正在运行的 Agent。
- 活跃子代理迁移暂不支持；不能在其父任务仍持有生命周期时单独卸载。

## Issue #10：标题

原实现调用底层 table.update，但已安装宿主的缓存表使用 get/put。现在以完整 identity/rows 读取并写回，在 attachSession 发布新归属之前对齐 identity.cwd；保留 title 行，移除旧 workingDirectory 行。attach 失败恢复原 identity/rows。

本机“标题保留测试”归档后，标题仍保存在新版 per-record 投影缓存中；修复面板原来只读取旧 session_projcache.json 汇总文件，因此误显示“未命名会话”。现在扫描、归档、预览和备份列表按内存缓存、新版单记录文件、旧版汇总、档案标题的顺序读取。回归测试覆盖新旧缓存共存、内存更新和损坏缓存降级。

报告者 DSH 0.2.0-rc.2 环境尚未直接复现；这是发现并修复的具体代码缺陷，不声称已完成该环境验收。

## Desktop 验收

1. 保存正在做的工作，从应用菜单或托盘彻底退出 DSH，再启动。自检版本应为 2.4.2-rc.4。
2. 新建测试会话并命名“标题保留测试”，发送一句消息，等回复结束。拖到 B，确认后应直接显示在 B，无 pending、无需重启。
3. 不切换到其他会话，在 B 当前界面直接连续发两条消息，确认输入框可用、正常回复，模型/预设/权限及未发送草稿保持预期，有效工作目录为 B。
4. 让另一个测试会话执行可随时停止的任务，生成回复期间拖动。先取消，原任务继续；再次拖动选择“停止任务并迁移”，确认任务停止后会话出现在 B，可继续发送。
5. 重启后标题、历史、归属和工作目录仍正确。分别检查手动标题和自动生成标题，并在归档后检查设置中的会话修复列表标题。若异常，保留测试会话，不重复强行搬移。
